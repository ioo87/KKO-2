# KKO.com — โครงสร้างไฟล์

แยกเป็น 3 ไฟล์หลัก เก็บไว้ในโฟลเดอร์เดียวกัน (สำคัญ ห้ามแยกโฟลเดอร์ ไม่งั้นลิงก์ระหว่างไฟล์จะพัง):

```
kko-app/
├── index.html   ← โครงสร้างหน้าเว็บ (login, เมนู, ตัวแปลงไฟล์)
├── style.css    ← ดีไซน์ทั้งหมด
├── script.js    ← โค้ดการทำงานทั้งหมด (ล็อกอิน, เมนู, แปลงไฟล์)
└── README.md    ← ไฟล์นี้
```

## วิธีเปิดใช้งาน
ดับเบิลคลิก `index.html` เปิดในเบราว์เซอร์ได้เลย ไม่ต้องติดตั้งอะไรเพิ่ม ไม่มีการเชื่อมต่อเซิร์ฟเวอร์ภายนอกใดๆ ทั้งสิ้น (ทำงานได้แม้ไม่มีเน็ต) — ถ้าจะเอาขึ้นเว็บจริง อัปโหลดทั้ง 3 ไฟล์ขึ้น hosting ที่ไหนก็ได้ (Netlify, Vercel, GitHub Pages ฯลฯ)

## ทำไมปุ่ม "บัญชีทดลอง" ก่อนหน้านี้ถึงพังจนขึ้น SyntaxError
เวอร์ชันก่อนหน้าโหลดสคริปต์ Google (`accounts.google.com/gsi/client`) จากภายนอก ซึ่งพรีวิวในแชทของ Claude บล็อกโดเมนนี้ไว้ (อนุญาตแค่บาง CDN เท่านั้น) พอสคริปต์โหลดไม่สำเร็จแบบผิดปกติ มันทำให้เกิด error ประเภท "Unexpected end of input" และระบบล็อกอินค้าง

**วิธีแก้ในเวอร์ชันนี้:** เอาการพึ่งพาสคริปต์ภายนอกออกทั้งหมด ปุ่ม "ลงชื่อเข้าใช้ด้วย Google" ตอนนี้ทำงานในเครื่องล้วนๆ (ไม่ยิง request ออกไปไหนเลย) กดแล้วเข้าเมนูได้ทันที ทำงานเสถียร 100% ไม่ว่าเน็ตจะช้าแค่ไหนหรือมือถือสเปคต่ำแค่ไหน

## เกี่ยวกับการล็อกอิน (สำคัญ อ่านตรงนี้)
ตอนนี้ปุ่ม Google เป็น **UI จำลอง** (หน้าตาเหมือนจริง กดแล้วเข้าใช้งานได้ปกติ) ไม่ได้ยืนยันตัวตนกับ Google จริงๆ เพราะการเชื่อม Google OAuth ของจริงต้องมี:
1. Client ID จาก [Google Cloud Console](https://console.cloud.google.com) (สร้างฟรี)
2. โดเมนจริงที่คุณเอาเว็บนี้ไปติดตั้ง (ลงทะเบียนใน "Authorized JavaScript origins")

สิ่งเหล่านี้ใช้งานไม่ได้ในพรีวิวของแชท ต้องรอจนกว่าคุณจะเอาไฟล์นี้ไปโฮสต์บนโดเมนจริงก่อน

**เมื่อพร้อมจะเชื่อมของจริง** ให้ทำตามนี้ใน `index.html` และ `script.js`:

1. เพิ่มใน `<head>` ของ `index.html`:
```html
<script src="https://accounts.google.com/gsi/client?hl=th" async defer></script>
```

2. แทนที่ event listener ของ `googleLoginBtn` ใน `script.js` ด้วย:
```js
google.accounts.id.initialize({
  client_id: "ใส่ CLIENT_ID จริงของคุณที่นี่.apps.googleusercontent.com",
  callback: (response) => {
    const payload = JSON.parse(atob(response.credential.split('.')[1]));
    currentUser = { name: payload.name, picture: payload.picture };
    enterApp();
  }
});
google.accounts.id.renderButton(
  document.getElementById('googleLoginBtn').parentElement,
  { theme: 'filled_black', size: 'large', shape: 'pill', text: 'signin_with' }
);
```

## เกี่ยวกับไฟล์ MP3 ที่ได้
ตัวแปลงไฟล์สกัดเสียงจากวิดีโอได้จริง แต่ไฟล์ที่ได้เป็น **WAV ที่ตั้งชื่อเป็น .mp3** ไม่ใช่ไฟล์ MP3 (MPEG) จริง เล่นได้ปกติในเครื่องเล่นทั่วไป แต่ขนาดไฟล์จะใหญ่กว่า MP3 จริงมาก ถ้าต้องการเข้ารหัส MP3 จริง ต้องเพิ่มไลบรารีเข้ารหัส เช่น `lamejs` — บอกได้เลยถ้าอยากให้เพิ่มให้

## สิ่งที่ปรับเพื่อรองรับมือถือสเปคต่ำ (RAM 4GB ขึ้นไป)
- ไม่มีการโหลดทรัพยากรจากภายนอกเลย (ไม่มี Google Fonts, ไม่มี Google script) → โหลดเร็ว ไม่ค้างรอเน็ต
- ใช้ AudioContext ตัวเดียวซ้ำ แทนสร้างใหม่ทุกครั้งที่แปลงไฟล์ → กันเครื่องค้าง/ชนลิมิตหลังแปลงหลายรอบ
- ลด blur effect ลง และมีพื้นหลังทึบสำรองถ้าเบราว์เซอร์/เครื่องไม่รองรับ backdrop-filter ดีพอ
- ตัด `background-attachment: fixed` ที่ทำให้สกอลล์กระตุกบนมือถือ
- แอนิเมชันคลื่นเสียงตกแต่งจะหยุดนิ่ง ไม่วนตลอดเวลา (ประหยัดแบตเตอรี่/CPU) เหลือแค่ตอนกำลังโหลดจริง
- แจ้งเตือนก่อนถ้าไฟล์วิดีโอใหญ่เกิน ~200MB เพราะขั้นตอนถอดรหัสเสียงเป็นจุดที่กินแรมมากสุด

## ตรวจสอบช่องโหว่ความปลอดภัย (Security Review)

ตรวจตามหัวข้อที่แจ้งมา สรุปผลและสิ่งที่แก้ไปแล้ว:

### สิ่งสำคัญที่ต้องเข้าใจก่อน: เว็บนี้ไม่มีเซิร์ฟเวอร์
`index.html` / `style.css` / `script.js` ทำงาน **ทั้งหมดในเบราว์เซอร์ของผู้ใช้เอง** ไม่มี backend ไม่มีฐานข้อมูล ไม่มีที่เก็บไฟล์บนเซิร์ฟเวอร์ ไฟล์ MP4/รูปภาพที่คนเลือก **ไม่เคยถูกส่งออกไปไหนเลย** ประมวลผลอยู่ในแท็บของเขาเอง แล้วก็หายไปเมื่อปิดแท็บ

นี่หมายความว่า: **ถ้ามีคนเลือกไฟล์อันตรายขึ้นมา มันกระทบแค่เครื่อง/แท็บของเขาเอง (ซึ่งเบราว์เซอร์ป้องกันไว้อยู่แล้ว) ไม่มีทาง "ทำลายเว็บไซต์ของคุณ" ได้ เพราะไม่มีอะไรของคุณให้มันไปแตะถึง** ต่างจากเว็บที่มีเซิร์ฟเวอร์รับไฟล์อัปโหลดจริงๆ (ซึ่งเสี่ยงเรื่อง webshell, RCE ฯลฯ) — เว็บแบบ static ล้วนๆ แบบนี้ไม่มีความเสี่ยงกลุ่มนั้นอยู่แล้วโดยโครงสร้าง

### 1. Cookie
ไม่ใช้ cookie เลยทั้งเว็บ (ตรวจสอบแล้ว ไม่มี `document.cookie` ที่ไหนในโค้ด) → ไม่มีอะไรให้ขโมย ไม่มี session cookie ให้ hijack

### 2. Code Logic
- **พบและแก้แล้ว:** ตอน "เลือกรูปปก" โค้ดเดิมเอาชื่อไฟล์ (`file.name`) ไปแปะผ่าน `innerHTML` — ชื่อไฟล์เป็นสิ่งที่ผู้ใช้ควบคุมได้เอง (ตั้งชื่อไฟล์เป็นอะไรก็ได้ รวมถึงใส่โค้ด HTML/JavaScript ในชื่อไฟล์) นี่คือช่องโหว่ **DOM-based XSS** ตัวจริง แก้แล้วโดยเปลี่ยนเป็น `textContent` ซึ่งเบราว์เซอร์จะไม่แปลความเป็น HTML ให้
- **สิ่งที่ควรรู้ (ไม่ใช่บั๊ก แต่เป็นข้อจำกัดโดยธรรมชาติ):** สถานะ "ล็อกอินแล้ว" ตอนนี้เป็นแค่ตัวแปร JavaScript ในเครื่อง ใครเปิด dev tools ก็ข้ามหน้า login ได้เลย — **นี่ปกติสำหรับเว็บที่ไม่มี backend** เพราะไม่มีข้อมูล/ทรัพยากรอะไรให้ป้องกันจริงๆ อยู่หลังบ้านอยู่แล้ว แต่ถ้าวันหนึ่งมีข้อมูลจริงจังที่ต้องป้องกัน (เช่นไฟล์ของผู้ใช้แต่ละคน, ประวัติการใช้งาน) **ห้ามพึ่งการเช็คฝั่ง client เพียงอย่างเดียวเด็ดขาด** ต้องมี backend ที่ตรวจสิทธิ์จริงทุกครั้ง

### 3. Session
ไม่มี server session เพราะไม่มีเซิร์ฟเวอร์ ไม่มี `localStorage`/`sessionStorage` เก็บ token ใดๆ (ตรวจสอบแล้ว) ถ้าอนาคตทำ backend จริง ให้ใช้ cookie แบบ `HttpOnly; Secure; SameSite=Strict` สำหรับ session ไม่ควรเก็บ token ไว้ใน localStorage เพราะถ้ามี XSS หลุดจะขโมย token ไปใช้ได้ทันที

### 4. Metadata
- ไฟล์ที่เลือก (วิดีโอ/รูป) ไม่ถูกอ่าน metadata (EXIF/GPS ฯลฯ) หรือส่งออกไปไหนเลยในโค้ดปัจจุบัน ไม่มีการรั่วไหลของข้อมูลส่วนตัวจากไฟล์
- เพิ่ม security header ผ่าน `<meta>` ใน `index.html`: **Content-Security-Policy** (จำกัดให้โหลดสคริปต์/สไตล์/สื่อได้จากไฟล์ในโดเมนตัวเองเท่านั้น ปิด `<object>`/`<embed>`/`<form>` ทั้งหมด) และ **Referrer-Policy** (ลดข้อมูลที่รั่วไปเว็บอื่นตอนมีลิงก์ออก)
- **ข้อจำกัดของ meta tag:** บาง header อย่าง `X-Frame-Options`, `X-Content-Type-Options`, และ `frame-ancestors` ตั้งผ่าน `<meta>` ไม่ได้จริง ต้องตั้งเป็น HTTP header จริงตอน deploy ดูตัวอย่างด้านล่าง

### 5. ไฟล์อัปโหลด (MP4 / รูปปก)
เพิ่มการป้องกันหลายชั้นใน `script.js`:
- เช็ค `file.type` จริงก่อนประมวลผลทุกครั้ง (attribute `accept` บน `<input>` เป็นแค่ตัวกรองหน้าตา ข้ามได้ง่ายๆ โดยเลือก "ไฟล์ทั้งหมด" หรือลาก-วางไฟล์อื่นเข้ามา) — ถ้าไม่ใช่ประเภทที่ถูกต้อง ปฏิเสธทันทีพร้อมข้อความแจ้งเตือน
- จำกัดขนาดไฟล์: วิดีโอไม่เกิน 500MB (แข็ง), รูปปกไม่เกิน 10MB — กันเครื่องสเปคต่ำแฮงก์/หน่วยความจำเต็มตั้งแต่ตอนเลือกไฟล์ ไม่ต้องรอไปพังตอนแปลง
- ไฟล์วิดีโอ/รูปที่เลือกจะถูกส่งเข้า Web Audio API (`decodeAudioData`) เท่านั้น ซึ่งเป็นฟังก์ชันมาตรฐานของเบราว์เซอร์ที่ทำ sandbox ไว้อยู่แล้ว ไม่มีการ "รัน" ไฟล์เป็นโค้ดในทางใดทางหนึ่ง — ถ้าไฟล์ไม่ใช่สื่อจริงๆ มันแค่ decode ไม่สำเร็จแล้วโชว์ error สุภาพ ไม่มีทางถูกใช้เป็นช่องทางรันโค้ดอันตราย
- ชื่อไฟล์ MP3 ที่ดาวน์โหลด (มาจากช่อง "ชื่อเพลง" ที่ผู้ใช้พิมพ์เอง) ตอนนี้ถูก sanitize ตัดอักขระที่เสี่ยง/ผิดกฎของชื่อไฟล์ออกก่อนเสมอ

### สำหรับตอน deploy จริง (ตั้งค่าที่ hosting)
เพิ่ม HTTP header เหล่านี้ที่ hosting provider (meta tag ตั้งไม่ได้จริง) ตัวอย่างสำหรับ Netlify — สร้างไฟล์ชื่อ `_headers` วางคู่กับไฟล์อื่นๆ:
```
/*
  X-Frame-Options: DENY
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self'; media-src 'self' blob:; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none';
```
ถ้าใช้ hosting อื่น (Vercel, GitHub Pages, Cloudflare Pages ฯลฯ) หลักการเดียวกัน แค่รูปแบบไฟล์ config ต่างกัน บอกได้ถ้าอยากให้ช่วยตั้งให้ตาม provider ที่ใช้จริง

### หมายเหตุ: ทดสอบด้วย file:// ในเครื่อง
ถ้าเปิด `index.html` ตรงๆ (ดับเบิลคลิก) แล้วหน้าเว็บดูแปลกๆ/สไตล์ไม่ขึ้น ให้ลองลบบรรทัด `<meta http-equiv="Content-Security-Policy" ...>` ออกชั่วคราว (บางเบราว์เซอร์จัดการ CSP กับไฟล์ local แปลกกว่าไฟล์บนเว็บจริง) หรือใช้เซิร์ฟเวอร์เล็กๆ ทดสอบแทน เช่น `python3 -m http.server` แล้วเปิด `http://localhost:8000`

## อัปเดต: เพิ่มแท็บที่ 2 — แปลง รูปภาพ → PDF

### สิ่งที่เพิ่มเข้ามา
- **แถบสลับแท็บ (Tab Bar):** อยู่ในหน้าเดียวกัน สลับระหว่าง 🎵 MP4 to MP3 และ 🖼️ IMG to PDF ได้ทันที ไม่โหลดหน้าใหม่ (แค่ซ่อน/โชว์ panel ด้วย CSS ล้วนๆ)
- **เลือกได้หลายรูปพร้อมกัน:** ช่อง input รองรับ `multiple` เลือกรูปถ่ายเอกสารได้ทีละหลายใบ และเลือกเพิ่มได้เรื่อยๆ (ไม่ได้แทนที่ของเดิม)
- **พรีวิวรูปภาพ (Thumbnails):** โชว์รูปที่เลือกแล้วเป็น grid พร้อมปุ่ม × ลบทีละรูปได้
- **จัดหน้า A4 อัตโนมัติ:** ใช้ jsPDF คำนวณสัดส่วนภาพเทียบกับขนาดหน้า A4 (210×297mm มีขอบ 10mm) ย่อ/ขยายให้พอดีโดยไม่บิดสัดส่วน แล้ววางกึ่งกลางหน้าเสมอ — รูปแนวตั้ง แนวนอน หรือสี่เหลี่ยมจัตุรัส ก็ไม่เบี้ยว ไม่หลุดขอบ
- แต่ละรูป = 1 หน้า PDF เรียงตามลำดับที่เลือก
- ปุ่มดาวน์โหลด, ดูตัวอย่าง PDF (เปิดแท็บใหม่), และแชร์ไฟล์ (รองรับมือถือที่เปิด Web Share API)

### Library ที่ใช้เพิ่ม: jsPDF
โหลดจาก `cdnjs.cloudflare.com` (CDN สาธารณะที่เชื่อถือได้ ใช้กันทั่วไป) — เพิ่มโดเมนนี้ไว้ใน CSP (`script-src`) แล้วโดยเฉพาะ ไม่ได้เปิดกว้างให้โดเมนอื่น

### ข้อจำกัดที่ตั้งใจไว้ (กันเครื่องสเปคต่ำแฮงก์)
- เลือกได้สูงสุด **40 รูปต่อ PDF หนึ่งไฟล์** (แต่ละรูปต้องโหลดเข้าหน่วยความจำเพื่อวาดลง canvas ก่อนใส่ PDF)
- รูปแต่ละใบไม่เกิน **25MB**
- ระบบ flatten รูปที่มีพื้นหลังโปร่งใส (PNG) เป็นพื้นขาวก่อนเสมอ กันปัญหาพิมพ์ออกมาดำ

### ฟังก์ชันแรก (MP4 → MP3) ยังอยู่ครบ
ไม่มีอะไรเปลี่ยนในฟังก์ชันแปลงเสียง แค่ย้ายไปอยู่ใต้แท็บแรกของหน้า workspace เดียวกัน
